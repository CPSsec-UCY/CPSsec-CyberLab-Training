## The problem in one sentence

Lattice cryptography needs to multiply pairs of degree-255 polynomials over a finite field, and the obvious method does about $256^2 = 65{,}536$ coefficient products per multiplication. A single ML-KEM operation performs many such products. That is too slow.

## The FFT analogy

The Number Theoretic Transform is the finite-field cousin of the Fast Fourier Transform. The idea is:

1. **Transform** each polynomial into a different representation where multiplication is easy.
2. **Multiply point by point** — one multiplication per coefficient instead of one per coefficient pair.
3. **Inverse transform** back to the ordinary coefficient representation.

In the transformed domain, multiplication is linear in the number of coefficients. The transform itself costs $O(n \log n)$, so the total is $O(n \log n)$ instead of $O(n^2)$.

<Callout variant="note" title="Why the ring has X^n + 1, not X^n − 1">
ML-KEM works in $R_q = \mathbb{Z}_q[X]/(X^n + 1)$. When a product term has degree at least $n$, it wraps around with a minus sign. This is called **negacyclic** convolution, and it is why the transform evaluates at odd powers of a root of unity rather than at all powers.
</Callout>

## Where the time goes

For ML-KEM-768, one encapsulation or decapsulation runs several NTTs and point-wise products. The transform and Keccak hashing dominate the cycle count. Making the NTT fast, branch-free and vector-friendly is a core engineering problem, not an optional optimisation. <Cite id="fips203" locator="§4.3" />

## A concrete cost

For $n=256$, naive negacyclic multiplication needs about $256^2 = 65{,}536$ coefficient products. ML-KEM performs several such products per encapsulation or decapsulation, so the naive approach would dominate the CPU budget. The NTT reduces the transform and point-wise work to a few thousand butterflies, then a small base-case multiply.

The speed-up is not only asymptotic. The transform's memory access pattern is regular enough to vectorise, while the schoolbook product has a much larger working set and more multiplications per output.

### Count operations before counting cycles

For $n=256$, a complete radix-2 transform would use $256\log_2(256)/2=1{,}024$ butterflies. ML-KEM's incomplete transform stops one layer earlier, at $7\cdot128=896$ butterflies. One polynomial multiplication using that transform requires two forward transforms and one inverse transform, then 256 point-wise products and 128 residual two-coefficient multiplications. With four field products in each base case, that is

$$
3\cdot896+256+128\cdot4=3{,}456
$$

field multiplications; a three-product Karatsuba base case saves one variable-by-variable product but still needs a multiplication by the public residual twiddle $\zeta$, so it also uses four field multiplications per block unless that fixed multiplication is precomputed into an operand. Schoolbook negacyclic multiplication uses $65{,}536$ field products. These counts exclude additions, modular reductions, twiddle loads and memory movement, so they are an arithmetic comparison rather than a timing prediction. <Cite id="fips203" locator="§4.3–4.3.1" /> <Cite id="kyber-spec" locator="§2.3–2.4" />

| Implementation model | Field multiplications per degree-255 product | Main omitted cost |
| --- | ---: | --- |
| Schoolbook | 65,536 | Accumulation and final reduction |
| Complete NTT, if the root existed | $3\cdot1{,}024+256=3{,}328$ | Eight layers per transform across three transforms |
| ML-KEM incomplete NTT, standard base case | 3,456 | Seven layers, point-wise work and residual blocks |
| ML-KEM incomplete NTT, Karatsuba before fixed-twiddle optimisation | 3,456 | Three variable products plus one public-twiddle product per block |

A complete transform is not available over $\mathbb{Z}_{3329}$ for this negacyclic ring, even though the field has a 256th root. The comparison is included to separate the cost of incompleteness from the benefit of transform-based multiplication.

## The engineering threat model

The primary failure is usually not a cryptanalyst attacking the transform. It is a correct-looking implementation computing the wrong ring product, overflowing a lane, or using an unreduced public value where the standard requires a canonical representative. A single wrong twiddle can produce a polynomial that still has the right length and passes superficial checks but changes every key or ciphertext derived from it. In a KEM, that means honest parties may fail to agree; in a signature, it can mean invalid signatures or unsafe secret distributions if the error affects rejection logic.

Use a concrete firmware scenario. A device library switches from a scalar NTT to an AVX2 implementation. Interoperability fails only for keys with certain coefficient patterns. The defender's first goal is algebraic equivalence: for every input, the new routine must return exactly the coefficients of the specified ring product. The second goal is bounded arithmetic: no intermediate may overflow its chosen word or lane type. The third goal is constant-time execution: the access pattern and correction decisions must not depend on secret coefficients.

An attacker in this setting may submit malformed public keys or ciphertexts, tamper with firmware, or induce faults during decapsulation. The arithmetic implementation should reject non-canonical encodings before transform routines expand their scope. However, an NTT is a computational representation, not an authentication mechanism. It neither detects tampering nor makes a malformed polynomial safe.

Misconceptions are expensive here. An NTT does not eliminate modular reduction; it changes where reduction is needed. A full transform is not automatically more correct than an incomplete one; correctness comes from implementing the ring isomorphism and the residual multiplication. Equal timing on one benchmark does not establish constant time, because secret-dependent branches can be absent from that input set while present in the code. Finally, a transform round-trip checks only part of the system: forward and inverse routines can share the same inverse bug and still cancel.

Define invariants before optimising. Every coefficient has a documented range, every twiddle has a documented order, and every in-place stage has a documented layout. Keep a slow schoolbook multiplier as an oracle. Test products against that oracle before comparing speed, and keep the oracle in the test harness even after the optimised path becomes the default.

## The ring

ML-KEM uses

$$
R_q = \mathbb{Z}_q[X]/(X^{256} + 1), \qquad q = 3329.
$$

A polynomial is an array of 256 coefficients in $[0, q)$. Adding is coefficient-wise. Multiplying is negacyclic:

$$
c_k = \sum_{i+j=k} a_i b_j \;-\; \sum_{i+j=k+n} a_i b_j \pmod q.
$$

## Roots and layers

Because $q - 1 = 3328 = 2^8 \cdot 13$, the field has a primitive 256th root of unity $\zeta$ (for example 17) but **no** primitive 512th root. A full 256-point negacyclic NTT would need a 512th root, so ML-KEM uses a seven-layer **incomplete** NTT:

- 128 butterflies per layer,
- 7 layers, ending with 128 degree-one polynomials,
- a final 2×2 base-case multiplication that applies the remaining twiddle.

This is exactly the structure in the reference specification. <Cite id="kyber-spec" locator="§2.3" />

## Common pitfalls

- Forgetting the **negacyclic sign flip** gives a cyclic product, not the ring product.
- Using the wrong root order breaks the transform, even if the butterfly code looks correct.
- Reducing too late can overflow 16-bit lanes; reducing too often costs cycles.
- A secret-dependent branch in the butterfly loop turns a maths bug into a side-channel bug.



## A tiny worked example

In the toy ring $\mathbb{Z}_{17}[X]/(X^4+1)$, multiply

$$
a = 1 + 2X + 3X^2 + 4X^3, \qquad b = 1 + 2X + 3X^2 + 4X^3.
$$

Naive convolution gives coefficients $1,4,10,20,25,24,16$ before reduction. Subtracting the wrapped high-degree terms gives $(-24,-20,-6,20)$, which reduces to $(10,14,11,3)$. Schoolbook form uses 16 coefficient products. At $n=4$, the NTT is not faster: each of the three transforms has two layers of two butterflies, so $3\cdot4+4=16$ field multiplications are still required. The example demonstrates equivalence, not a speed-up.

## A coefficient-level walkthrough

Start with the negacyclic identity $X^n=-1$. For each pair $i,j$ with $0\le i,j<n$, the product $a_i b_j X^{i+j}$ contributes with a plus sign if $i+j<n$ and a minus sign if $i+j\ge n$. Accumulating into 256 bins is simple but does $n^2$ modular multiplications. Reducing every accumulation immediately costs more divisions than reducing once at the end with a proven bound.

The transform first changes the order of coefficients according to the butterfly network, often through bit reversal or a decimation-in-time/decimation-in-frequency convention. Each butterfly reads two values, multiplies one by a twiddle, and writes a sum and difference. The twiddle is public, so its table lookup is safe; the coefficients are secret, so their values must never select a table entry.

For the ML-KEM incomplete NTT, seven radix-2 layers produce 128 blocks of two coefficients. In each block, multiplication still obeys the original ring. If the block basis is $1,X$ and $X^2=\zeta$, then

$$
(a_0+a_1X)(b_0+b_1X)=a_0b_0+\zeta a_1b_1+(a_0b_1+a_1b_0)X.
$$

This base-case formula is where the last twiddle is applied. Schoolbook multiplication uses four field products: $a_0b_0$, $a_0b_1$, $a_1b_0$ and $a_1b_1$. Karatsuba reduces the variable-by-variable products to three by computing $p_0=a_0b_0$, $p_2=a_1b_1$ and $p_1=(a_0+a_1)(b_0+b_1)-p_0-p_2$, then forming the constant coefficient $p_0+\zeta p_2$ and the $X$ coefficient $p_1$. The multiplication by the public $\zeta$ is still a field multiplication unless it is folded into a precomputed operand. Omitting the $\zeta$ term is equivalent to using a cyclic relation and changes the scheme’s ring.

ML-KEM coefficients are encoded in 12 bits because $3329<2^{12}$. A decoder should accumulate the specified number of bytes, verify the input length, and reject a decoded value at least $q$. There are no spare 12-bit positions to mask: values from 3329 through 4095 are non-canonical. FIPS 203 checks an encapsulation key by decoding its coefficient region and re-encoding it; equality verifies that no coefficient exceeded $q-1$. <Cite id="fips203" locator="§4.2.1 and §7.2" /> A transform can reduce any field representative to the same value, so it must not become a permissive substitute for parsing. Similarly, an output encoder must write the canonical representative rather than an arbitrary congruent integer.

For a concrete two-coefficient packet, the canonical values $3281$ and $3328$ encode little-endian as `D1 0C 00 D0`: the first 12 bits are `D1 0C`, and the next 12 bits are `00 D0`. Changing the second pair to `FF 0F` decodes to $4095$, not to $4095\bmod3329=766$, and must fail the modulus check. Arithmetic performed after such a failure cannot repair an ambiguous public-key encoding.

| Invariant | Correct state | Useful negative test |
| --- | --- | --- |
| Coefficient domain | Every parsed public coefficient is in $[0,3329)$ | Try $3329$ and $4095$ in a 12-bit lane |
| Ring relation | $X^{256}=-1$, not $X^{256}=1$ | Multiply basis polynomials $X^{255}\cdot X$ |
| Root convention | The specified $\zeta=17$ and twiddle exponents | Check $\zeta^{128}=-1$ and independent basis vectors |
| Residual block | $X^2=\zeta$ within each final block | Omit the $\zeta$ term and compare with schoolbook |
| Output encoding | Canonical little-endian bit packing | Round-trip every supported coefficient depth |

A useful laboratory exercise is to replace one twiddle with its negative. A round-trip through forward and inverse transforms using that same wrong table may still look plausible for selected inputs, while multiplication disagrees with schoolbook convolution. This demonstrates why oracle tests need independent operations rather than only inverse-pair consistency.

## Negacyclic convolution as evaluation

Let $\psi$ be a primitive $2n$-th root of unity in $\mathbb{Z}_q$. The negacyclic NTT of $a \in R_q$ is

$$
\hat{a}_k = \sum_{j=0}^{n-1} a_j \, \psi^{(2k+1)j}, \qquad 0 \le k < n.
$$

The inverse is

$$
a_j = n^{-1} \psi^{-j} \sum_{k=0}^{n-1} \hat{a}_k \, \omega^{-jk}, \qquad \omega = \psi^2.
$$

The odd-power evaluation is equivalent to pre-twisting the coefficient vector by $\psi^j$ and applying a cyclic NTT with $\omega=\psi^2$; the inverse uses the corresponding factor $\psi^{-j}$. The ring and module variants, and their reductions, are covered in the standard lattice toolkit and survey literature. <Cite id="lpr2010" locator="pp. 1–23" /> <Cite id="lpr2013-toolkit" locator="pp. 35–54" /> <Cite id="peikert2016" locator="pp. 283–424" />

## Point-wise multiplication

  <NttWork />
</Figure>

Define the NTT-domain product $\hat{c}_k = \hat{a}_k \hat{b}_k$. Then

$$
\widehat{(a \cdot b)}_k = \hat{a}_k \hat{b}_k,
$$

and applying the inverse transform yields the negacyclic product in $R_q$. Correctness follows from evaluation: both sides are the product of the evaluations at $\psi^{2k+1}$.

## Complexity

A radix-2 butterfly layer performs $n/2$ butterflies, each with one multiplication and two additions modulo $q$. There are $\log_2 n$ layers, so the transform uses

$$
\frac{n}{2}\log_2 n \text{ butterflies} \quad\text{instead of}\quad n^2 \text{ coefficient products}.
$$

For $n = 256$: 1,024 butterflies versus 65,536 products. The asymptotic gain is real, but the constant factors — modular reduction, memory traffic, twiddle loads — determine the actual speed. <Cite id="longa2016" locator="pp. 124–139" />

## Why incomplete is not incorrect

ML-KEM stops at degree-one factors because $2n = 512$ does not divide $q - 1$. The remaining base-case multiplication

$$
(a_0 + a_1 X)(b_0 + b_1 X) \bmod (X^2 - \zeta)
$$

is still exact; it simply finishes the last layer with a dedicated formula. The standard specifies this decomposition precisely. <Cite id="fips203" locator="§4.3.1" />

<Callout variant="lab" title="Reduction sketch">
The NTT is a ring isomorphism from $R_q$ to a product of smaller fields (or degree-two extensions in the incomplete case). Correctness of multiplication follows from the Chinese Remainder Theorem: multiplication in the product ring is component-wise. The security of the scheme is separate; the NTT does not change the underlying lattice problem.
</Callout>



## Why the transform is correct

The negacyclic NTT evaluates a polynomial at the odd powers of a primitive $2n$-th root:

$$
\hat a_k = \sum_{j=0}^{n-1} a_j \psi^{(2k+1)j}.
$$

Substituting the inverse formula and collecting the coefficient of $a_\ell$ gives

$$
n^{-1}\psi^{-\ell}\sum_{k=0}^{n-1}\psi^{(2k+1)\ell}\omega^{-jk}
=
n^{-1}\sum_{k=0}^{n-1}\omega^{k(\ell-j)}.
$$

For $\ell=j$ this sum is $n$; for $\ell\ne j$ it is a geometric series with ratio $\omega^{\ell-j}\ne1$ and sum zero. The inverse therefore returns exactly the original coefficient $a_j$. The evaluation matrix is a Vandermonde matrix on $n$ distinct points, so its determinant is nonzero and the interpolation is unique.

Point-wise multiplication then preserves every evaluation because each evaluation point $\alpha=\psi^{2k+1}$ satisfies $\alpha^n=-1$. Reducing a product modulo $X^n+1$ does not change its value at $\alpha$. Applying the inverse interpolation must consequently return the unique reduced product in $R_q$. This proves the multiplication identity without appealing to an approximate Fourier transform.

The Chinese remainder view makes the incomplete case precise. Over $\mathbb{Z}_{3329}$,

$$
X^{256}+1=\prod_{j=0}^{127}(X^2-\zeta^{2j+1}),
$$

where $\zeta=17$ has order 256. Each quadratic is irreducible over the base field, with two distinct roots in $\mathbb{F}_{q^2}$ because the characteristic is odd. Thus $R_q$ is a product of 128 copies of $\mathbb{F}_{q^2}$. Seven butterfly layers reduce each polynomial to the quadratic factors; the final two-coefficient multiply handles each field component. This is why an incomplete transform is still a ring isomorphism. <Cite id="fips203" locator="§4.3.1" />

The root checks are short enough to keep as startup invariants. Since $q-1=3328=2^8\cdot13$, the order of any field element divides $3328$. Direct modular exponentiation gives $17^{128}\equiv-1\pmod{3329}$ and therefore $17^{256}\equiv1$. An order dividing $128$ could not produce $-1$ at exponent $128$, so the order is exactly $256$. A primitive $512$th root would require $512\mid3328$, which is false. These checks establish both the available cyclic transform length and the impossibility of completing the negacyclic transform entirely inside the base field.

### Representation changes are not free

An NTT-domain coefficient is still a field element, but its interpretation depends on layout. A residual block uses basis $1,X$ with $X^2=\zeta^{2\operatorname{BitRev}_7(i)+1}$; another implementation may pre-twist coefficients or store independent polynomial blocks in SIMD lanes. All of these can be correct, but a twiddle table copied between conventions is not.

| Convention choice | Correctness condition | Cost consequence |
| --- | --- | --- |
| Decimation in time versus frequency | Forward and inverse permutations are exact inverses | Changes shuffle placement and memory locality |
| Adjacent coefficients versus blocks in lanes | Base-case pairing matches the stored layout | Changes broadcasts and tail handling |
| Canonical versus lazy residues | Every later stage's bound includes the wider range | Trades reductions against overflow risk |
| Montgomery versus ordinary residues | Conversions bracket the operations that assume each form | Adds conversion work but can reduce inner-loop cost |

This is why a transform round-trip is necessary but insufficient. Two routines can share a permutation or scaling mistake and cancel it, while point-wise multiplication against an independent coefficient-domain oracle still fails.

## The algebra behind the butterflies

When a primitive $2n$-th root $\psi$ exists, evaluation at $\psi^{2k+1}$ is injective on degree-less-than-$n$ polynomials. To see this, evaluate the transform at two roots and take a linear combination that isolates a coefficient using the inverse matrix. The matrix entries form a Vandermonde matrix on distinct points, so its determinant is nonzero. The displayed inverse is therefore exact, not an approximate FFT.

The relation $X^n+1$ explains the odd powers. If $\alpha=\psi^{2k+1}$, then $\alpha^n=-1$. Reducing a product modulo $X^n+1$ preserves evaluation at every such $\alpha$, because replacing $X^n$ by $-1$ does not change the value at $\alpha$. Point-wise multiplication followed by inverse interpolation must consequently return the unique reduced polynomial. This is a direct correctness proof and also explains why using an even power of $\psi$ computes the wrong cyclic relation.

The Chinese remainder view makes the incomplete case precise. Over $\mathbb{Z}_{3329}$,

$$
X^{256}+1=\prod_{j=0}^{127}(X^2-\zeta^{2j+1}),
$$

where $\zeta=17$ has order 256 and $\zeta^2$ has order 128. Each quadratic factor has distinct roots because the characteristic is odd. The ring is therefore a product of 128 quadratic extension rings, not a product of 128 copies of the base field. Seven butterfly layers reduce each polynomial to the quadratic factors; the final two-coefficient multiply handles each extension ring. This is why an incomplete transform is still a ring isomorphism. <Cite id="fips203" locator="§4.3.1" />

Reduction must preserve the same arithmetic with bounded intermediates. Barrett reduction precomputes a reciprocal of $q$ and replaces division with multiplication and shifts. If $a$ is bounded so that the reciprocal estimate is accurate enough, a correctly rounded quotient is recovered and at most one conditional subtraction produces the residue. The conditional subtraction should be implemented with a mask, not a secret-dependent branch.

Montgomery multiplication uses $R=2^b$ with $\gcd(R,q)=1$. Precompute $q'=-q^{-1}\bmod R$. For an input $T<qR$, compute

$$
m=Tq'\bmod R,\qquad U=(T+mq)/R.
$$

By construction $T+mq$ is divisible by $R$, so the division is a shift, and $U\equiv TR^{-1}\pmod q$. A final conditional subtraction keeps the result below $q$. Converting into Montgomery form multiplies by $R$ modulo $q$; converting back multiplies by $R^{-1}$. The point is that division by a power of two replaces division by $q$, while the expensive reciprocal is precomputed. <Cite id="montgomery1985" locator="Vol. 44, pp. 519–521" />

The stated Montgomery input bound also gives an output bound. Since $m<R$ and $T<qR$,

$$
0\le U=\frac{T+mq}{R}<\frac{qR+Rq}{R}=2q.
$$

Thus at most one subtraction of $q$ is needed; the condition selects between $U$ and $U-q$ and should be implemented with a mask. Barrett reduction has a similar division-to-multiply substitution, but its reciprocal estimate is accurate only over a specified input interval. Outside that interval, the quotient can be wrong by more than one, so a single correction is no longer justified. <Cite id="harvey2014" locator="Vol. 60, pp. 113–119" />

### Integer bounds for coefficient-domain work

Bounds are easiest to audit in the coefficient domain, before any modular transform. For a degree-less-than-$n$ product, each output coefficient receives at most $n$ positive-index terms and $n$ wrapped negative-index terms.

| Representation | Per-coefficient absolute bound for $n=256$, $q=3329$ | Width implication |
| --- | ---: | --- |
| Canonical $[0,q-1]$ inputs | $n(q-1)^2=2{,}835{,}349{,}504$ | Fits unsigned 32-bit, not signed 32-bit |
| Centred inputs $[-1664,1664]$ | $2n\cdot1664^2=1{,}417{,}674{,}752$ | Fits signed 32-bit with room for final reduction |
| Either representation | Far above $2^{15}-1=32{,}767$ | A 16-bit accumulator cannot hold the raw convolution |

The centred bound uses all $2n$ possible contributing products and is conservative; an implementation may accumulate positive and negative parts separately or reduce periodically, but it must state the new invariant. Testing random inputs cannot establish an overflow bound because the dangerous case is the maximum sum, not the average.

A lazy butterfly bound follows the same pattern. If both inputs and the twiddle product are reduced into $[0,q)$, then $t<q$, $a_j+t<2q-2=6656$ and $a_j-t\in(-q,q)$, so signed 16-bit storage suffices after that butterfly. If the first sum is deliberately left at $B=6656$ but the next twiddle product is reduced, the next sum is below $B+q=9985$, still safe. If the next product is also left unreduced, it can approach $qB=22{,}157{,}824$, and the following sum approaches $22{,}164{,}480$; signed 16-bit storage is then invalid. “Two butterflies before reduction” is therefore not a complete specification: it must say which quantities remain unreduced at each boundary.

The bounds matter as much as the formula. A 16-bit accumulator cannot safely hold an arbitrary product of two unreduced 16-bit values plus an addend. Lazy reduction may allow coefficients to range above $q$, but the next butterfly and the next multiplication must still fit the chosen width. Prove a single invariant for each stage rather than relying on observed random inputs. Edge cases include zero, $q-1$, the largest negative centred representative, and a butterfly whose sum crosses the word boundary while its difference does not.

For performance, distinguish transform count from useful multiplication count. One full radix-2 transform has $n\log_2 n/2$ butterflies. ML-KEM's seven layers have $7\cdot128=896$ butterflies per transform, followed by the residual base-case work; calling it 1,024 full-transform butterflies describes the ideal complete transform but not the exact incomplete implementation. Benchmark the actual sequence and count point-wise products separately. <Cite id="longa2016" locator="pp. 124–139" />
</Lens>

## The inner loop

A typical forward butterfly computes

$$
t = \zeta \cdot a_{j+\ell}, \qquad a_{j+\ell} = a_j - t, \qquad a_j = a_j + t.
$$

Everything is modulo $q$. In practice implementations avoid `%` in the inner loop:

- **Barrett reduction** replaces division by a precomputed reciprocal.
- **Montgomery multiplication** keeps values in Montgomery form and uses shifts/masks.
- **Lazy reduction** allows intermediate values to grow within a safe bound, reducing less often.

Montgomery's method remains the standard way to avoid trial division in modular multiplication. <Cite id="montgomery1985" locator="Vol. 44, pp. 519–521" /> Harvey's work on NTT arithmetic develops tighter bounds and faster reduction strategies. <Cite id="harvey2014" locator="Vol. 60, pp. 113–119" />

## Data layout and SIMD

On x86 AVX2, coefficients are packed into 16-bit lanes and butterflies are vectorised across independent blocks. On Arm NEON/SVE the same idea applies with different lane widths. The enemy is not the arithmetic; it is shuffles, twiddle broadcasts, and memory traffic.

<Callout variant="warning" title="Constant-time is a separate requirement">
A vectorised NTT can still leak through secret-dependent memory access or branches. ML-KEM's implementation requirements call for constant-time behaviour; the NTT must not index tables with secret coefficients. <Cite id="fips203" locator="§3.3" />
</Callout>

## Memory and bandwidth

- **In-place** transforms avoid allocating a second coefficient array.
- **Twiddle tables** are small enough to stay in L1, but access patterns matter.
- **Keccak** is often the other hot loop; on some platforms the hash dominates the NTT.
- **Streaming** and in-place buffer reuse matter on microcontrollers with tens of kilobytes of RAM.

### Count the module-level multiplications too

A fast polynomial kernel can still be called in an inefficient order. For a rank-$k$ module, a matrix-vector product needs $k^2$ polynomial multiplications and a vector dot product needs $k$. ML-KEM-768 has $k=3$: encapsulation performs $k^2+k=12$ ideal polynomial products, decryption performs one dot product, and decapsulation performs that dot product plus a full re-encryption, for $k+12=15$. Key generation performs $k^2=9$. These counts exclude additions, hashing and sampling, but they explain why decapsulation has a different CPU budget from encapsulation. <Cite id="fips203" locator="§5–7" />

| Rank $k$ | KeyGen matrix-vector | Encapsulation | Decryption | Decapsulation including re-encryption |
| ---: | ---: | ---: | ---: | ---: |
| 2 | 4 | 6 | 2 | 8 |
| 3 | 9 | 12 | 3 | 15 |
| 4 | 16 | 20 | 4 | 24 |

The table counts complete ring multiplications, not NTT invocations. Cache a transform only when the surrounding algorithm can reuse it without changing the canonical representation or exposing secret-dependent control flow. For example, a public matrix may be stored in NTT form, while ciphertext components must be decompressed in the coefficient domain before the required dot product.

### A reproducible cost model

Report a small set of stage measurements rather than one end-to-end average: coefficient encoding and decoding, sampling, one forward and inverse NTT, residual base-case multiplication, point-wise multiplication, and Keccak. For each stage record cycles or nanoseconds, peak stack, static table bytes and cache behaviour on the target CPU. Then compare the sum with end-to-end time to expose framework overhead.

| Bottleneck | Measurement that reveals it | Design response |
| --- | --- | --- |
| Twiddle loads | Cache misses or load stalls per butterfly | Repack or broadcast public tables |
| Lane shuffles | Instructions per butterfly, not just vector instructions | Align lane layout with the butterfly order |
| Reduction | Division or variable-latency multiply in the inner loop | Use proved Barrett/Montgomery bounds |
| Memory traffic | Bytes moved per transformed polynomial | Transform in place and reuse workspaces |
| Hashing | Keccak share of decapsulation time | Use an approved accelerator or batch safely |

Performance work must preserve two properties at once: exact agreement with the coefficient oracle and a control flow independent of secret values. A benchmark input that never triggers a conditional subtraction does not demonstrate constant-time behaviour. Keep the scalar oracle, boundary corpus and generated-code audit in the release gate even when the vector backend wins every average timing comparison.

## From algebra to cycles

- **Barrett/Montgomery reduction** replaces division with multiply/shift; both must be branch-free.
- **Lazy reduction** lets values grow within a proven bound, reducing the number of reductions.
- **Twiddle tables** should fit in L1 and be accessed in a pattern that does not depend on secrets.
- **SIMD** packs 16-bit coefficients and vectorises independent butterflies; Arm NEON/SVE and x86 AVX2 have different lane layouts.
- **Keccak** is often the other hot loop in ML-KEM; optimising only the NTT may not move the end-to-end number much.

## Benchmarking honestly

Measure the transform, point-wise multiply, inverse transform and hashing separately. Report the CPU, compiler, optimisation level and whether the implementation is constant-time. A faster NTT that leaks through secret-dependent indexing is not an improvement.

## Implementation workflow

Begin with three independent coefficient-domain routines: encode, decode and schoolbook negacyclic multiplication. Give each a fixed buffer contract and an explicit coefficient range. Then add a forward transform, inverse transform and point-wise product. Differential tests should cover basis vectors, all-zero and all-$q-1$ inputs, sparse products, and random inputs over several seeds. Basis vectors reveal swapped stages; extremes reveal reduction mistakes; random inputs reveal twiddle-order errors.

Implement the base-case multiplication before optimising the layers. For ML-KEM, verify each quadratic block against $(X^2-\zeta)$ and compare the complete product with the oracle. Test the inverse scaling by checking the all-ones polynomial: its forward evaluations are either zero or $n$ at the relevant roots, and the inverse must recover every coefficient as one. This catches a missing $n^{-1}$ without requiring a reference implementation.

SIMD layout is an interface, not merely a loop rewrite. Decide whether adjacent coefficients or independent polynomial blocks occupy lanes. Mark alignment requirements, handle the tail without secret-dependent branches, and avoid unaligned loads that cross protected page boundaries. Precompute twiddles in the exact lane order used by the kernel. A scalar-to-vector conversion performed once per operation may be cheaper than shuffling inside every butterfly.

Use branch-free correction for modular subtraction. One pattern computes $d=a-b$, forms $m=d\gg(W-1)$ for a suitably signed representation, and adds $m\mathbin{\&}q$; another uses a comparison mask. Either way, test the generated assembly on the supported compiler versions. The source-level absence of an `if` is not enough if a library call, bounds check or division was lowered to a branch.

For $a,b\in[0,3329)$, a signed 16-bit difference lies in $[-3328,3328]$. With an arithmetic right shift, $m=d\gg15$ is $-1$ for a negative difference and $0$ otherwise, so $d+(m\mathbin{\&}3329)$ maps $-1$ to $3328$, $-3328$ to $1$ and $3328$ to itself. This is a useful unit test for sign extension and mask width. The result can reach $3328$, so it still fits unsigned 16-bit storage but must be interpreted with the documented representative convention. A logical rather than arithmetic shift, or a mask widened at the wrong stage, silently breaks the correction.

Profile the stages separately. Record cycles per transform, point-wise product, inverse transform, coefficient packing and Keccak call. Report both median and a high percentile under a realistic workload. On an embedded target, also record peak stack, static table size and cache misses. A kernel that is faster when hot but requires an impractical prefetch table may lose end to end.

Operationally, version the coefficient representation and ring parameters together. A public key generated with one root convention must not be decoded by a routine using another. Firmware should authenticate the implementation identifier before accepting a cryptographic key, and rollback should restore a compatible pair. Keep a known-answer corpus that includes every parameter set and an independent library result for each test input.

Troubleshoot a mismatch by reducing the problem size. First test field multiplication and reduction, then one butterfly, then the transform inverse, then the base case, and only then the full pipeline. Print public test vectors with stage boundaries so a colleague can compare the first divergent value. Never print secret production coefficients; use a deterministic test key in an isolated debugging harness.
</Lens>

## Common failure modes

| Failure | Typical cause | Detection | Prevention |
| --- | --- | --- | --- |
| Cyclic instead of negacyclic product | High-degree terms are added rather than subtracted | Schoolbook oracle mismatch on basis products | Implement $X^n=-1$ explicitly in the oracle |
| Wrong twiddle order | Primitive root or exponent table is misindexed | Random products disagree while lengths look valid | Verify root order and test basis vectors |
| Incomplete base case uses $X^2=1$ | Residual twiddle is omitted | Error appears after point-wise multiplication | Use the quadratic-block formula and KATs |
| 16-bit lane overflow | Lazy reduction bound ignores a later add or product | Failure concentrated on dense inputs | Prove bounds per stage and widen or reduce |
| Missing inverse scale | $n^{-1}$ is omitted | Round-trip may fail or products may be scaled | Test the all-ones polynomial independently |
| Non-canonical input accepted | Transform reduces values that the parser should reject | Malformed public key reaches arithmetic | Validate 12-bit values before transformation |
| Secret-dependent correction | Reduction uses a branch or table indexed by a coefficient | Timing or taint analysis flags the loop | Use masks and audit generated code |

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Sparse tests pass, dense tests fail | Accumulator or lazy-reduction bound is too large | Add boundary-heavy differential tests and reduce earlier |
| Forward and inverse cancel the error | Shared twiddle or scale bug | Test each direction against an independent oracle |
| Only SIMD fails | Lane order, tail handling or alignment differs | Compare scalar and vector layouts coefficient by coefficient |
| Product fails only after seven layers | Residual base case is wrong | Check $X^2=\zeta$ and each quadratic block |
| Intermittent KEM disagreement | Wrong public root convention or malformed decoding | Pin the parameter version and validate canonical inputs |
| Optimised build is faster but flagged by taint analysis | Compiler introduced a conditional path | Inspect assembly and use audited reduction primitives |

## Design review checklist

- [ ] The ring modulus, coefficient width and canonical input range are documented.
- [ ] The root of unity and every twiddle exponent are generated or verified independently.
- [ ] Seven layers and the residual quadratic multiplication match the standard.
- [ ] Every lazy-reduction stage has a proved upper and lower bound.
- [ ] Addition, subtraction and multiplication have boundary tests at 0 and $q-1$.
- [ ] A schoolbook negacyclic oracle checks random and structured products.
- [ ] Forward, inverse and point-wise routines are tested independently.
- [ ] SIMD lane layout, alignment and tail handling are explicit.
- [ ] Generated code has no secret-dependent branch, address or division.
- [ ] Encoders and decoders reject wrong lengths and non-canonical values.
- [ ] Benchmarks report CPU, compiler, flags, stage costs and memory use.
- [ ] Firmware and libraries pin compatible parameter and implementation versions.

## Key takeaways

- The NTT turns polynomial convolution into point-wise multiplication.
- Negacyclic rings require evaluation at odd powers of a $2n$-th root.
- ML-KEM uses an incomplete NTT because 512 does not divide $q-1$.
- Reduction, memory layout and vectorisation determine real performance.
- Constant-time behaviour is a separate requirement from speed.
